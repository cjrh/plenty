# Serialization measurements

Issue #781 required measurements and review of ordinary handwritten hooks
before adding `@serial`. The same hooks are generated by derivation; JSON and
TOML algorithms stay in Plenty. These measurements record costs, not a promise
that typed codecs outperform a specialized event loop.

## Reproduce

Build the checkout's compiler, then run:

```sh
python3 -B scripts/serial_measure.py \
  --compiler target/debug/plenty --out target/check-timings/serial \
  --formats json toml --modes plain manual derived --repeat 3 \
  --throughput --mixed
```

The output directory retains generated sources, cold application objects,
runtime binaries, compiler logs, fixture bytes and `results.json`. Reports
include the compiler's version and hash, source revision, individual samples
and medians. Compiler invocations disable both function and program caches.
Application objects exclude the Rust runtime archive. Generated programs use
the optimized default, even when the compiler itself is a debug build.

The host was x86-64 Linux. Other workers shared the machine, so small elapsed
differences are noise; no historical speedup is inferred from the JSON
reference's measurements on a different compiler and host configuration.

## Gate before derivation

Each program contains 200 distinct ten-field classes and reaches encode and
decode for every class. The plain program constructs and reads the same
classes without codecs. Three cold samples gave:

| Format | Plain median | Handwritten median | Plain object | Handwritten object |
|---|---:|---:|---:|---:|
| JSON | 0.734 s | 4.703 s | 690,632 bytes | 15,132,136 bytes |
| TOML | 0.494 s | 4.568 s | 690,224 bytes | 16,039,264 bytes |

The added codec functionality and per-class specialization have substantial
compile and object costs. An earlier separate-slot handwritten decoder also
exceeded the existing 256-local compiler limit at 64 fields. Keeping typed
`Option` slots in one tuple and using ordinary `read_field` / `require_field`
helpers fixed the actual 64-field typed load without changing that limit.

Independent review accepted continuing with ordinary checked-hook derivation
and explicit cost reporting. It required final comparisons against equivalent
handwritten hooks, constructor-default error/order checks, hygienic names,
semantic aliases, enum validation and a wide-record regression.

## Structured 8 MB JSON workload

The [JSON cost record](../design/stdlib/json.md#costs) describes an
8,388,872-byte document of 34,393 objects and 687,862 events. Its historical
row contents were not retained. `--mixed` reconstructs those exact dimensions
with nine fields per object: one ASCII string and eight integers. Padding is
distributed across strings to reach the exact byte count. The fixture's
SHA-256 is `de992b1bf857c5b0a440cee3400def6036e11ccefac95e0493e4ddc35d5510ae`.

Before derivation, three process samples gave these medians for one operation:

| Operation | Time |
|---|---:|
| Typed decode with handwritten hooks | 0.597 s |
| Parse to a `Json` tree | 0.744 s |
| Scan all events without retaining values | 0.425 s |
| Typed encode with handwritten hooks | 0.118 s |
| Encode an existing `Json` tree | 0.0785 s |

Typed decoding builds application records and checks their schema. Event
scanning builds no application result. Tree operations build or traverse a
different result representation. These are useful cost comparisons, not
equivalent computations or a claim of event-speed parity.

## String and name-dispatch probes

`--throughput` additionally encodes and decodes a single 8 MiB ASCII text field
five times. Before derivation, typed/tree/event encoding each took about
14 ms for five operations. Typed decoding took about 77 ms, versus 29 ms for
tree parsing and 19 ms for a minimal direct decoder that omits field-schema
validation. Long-string bulk scans make this a different workload from the
many-token structured document.

The same executable measures raw member-name dispatch over 4, 16 and 64
integer fields, including parsing and decoder setup, for 2,000 documents.
Median times were 15.95, 50.86 and 202.30 ms. These loops isolate name
dispatch; a separate actual typed 64-field load checks that wide records
compile and decode correctly. The numbers do not establish a need for a
different name-dispatch algorithm.
